4 — Print Integration (detailed)

Requirements: Support thermal printers via ESC/POS; support Bluetooth Classic & BLE discovery/use, and USB printers. Allow Admin to configure printers per terminal.

Implementation approach (cross-platform)

Abstraction layer: implement PrinterService in the app that exposes consistent methods:

listDevices() → enumerates Bluetooth & USB printers.

connect(deviceId) → connect to chosen device.

printReceipt(payload) → sends ESC/POS bytes or PDF fallback.

disconnect(), status().

Bluetooth detection / connection:

Use a single abstraction that picks the native library per platform:

Android (native / React Native): use Android BluetoothAdapter / BluetoothSocket (classic) and support BLE scanning for BLE-capable printers.

iOS: CoreBluetooth (BLE) and ExternalAccessory (for MFi/accessory devices). Note: iOS classic Bluetooth for non-MFi printers is limited; prefer AirPrint or network printers on iOS.

Web (PWA on tablet): Web Bluetooth API where supported; fallback to Cloud Print or server-side print job to a network printer.

On multi-platform projects, use cross-platform plugins that wrap native APIs (e.g., React Native plugins or Capacitor plugins). The app layer calls PrinterService.listDevices() — the native plugin handles platform differences.

USB printing:

Android: use Android USB Host API to enumerate USB printers and open a raw connection to send ESC/POS commands.

iOS: USB support is limited; prefer network or AirPrint. If iPad with USB-C supports accessories, you may need MFi or vendor SDKs.

Web: Use WebUSB where supported; otherwise recommend a local print helper app/agent that receives jobs from tablet via local network.

Protocol: ESC/POS raw commands for receipts (line feeds, cut command, QR code). Also support generating PDF for A4 printing if printer not ESC/POS capable.

Same library for Bluetooth detection: build or use an adapter plugin that detects both Classic & BLE devices and normalizes the devices to a single list. If using a cross-platform framework, choose a plugin that supports both or combine two native modules behind one JS/native wrapper.

Printer profile: store commands like line width (chars per line), cut command, encoding (UTF-8), and special ESC/POS sequences for Arabic script shaping.

Receipt design: Simple text + logo + items table + totals + VAT/tax lines + QR for payment or feedback. Arabic shaping support is required — convert UTF-8 to printer-specific encoding or use graphic rendering (render receipt as bitmap then print).

Failover & testing

If connection fails, show clear error and allow re-try.

Queue print job and retry automatically up to N times; allow re-print from order history.

Provide printer test page in settings with sample Arabic & French text.

7 — Edge Cases & Important Implementation Notes

Arabic printing: ESC/POS printers may not support Arabic shaping natively — render receipt as image/bitmap for guaranteed correct Arabic display.

Offline mode: queue changes locally with timestamps and device/terminal id; on conflict, prefer server last-writer-wins or present reconciliation.

Security: secure printer endpoints and do not expose unrestricted raw printing from the server. Printer connections should be device-local or initiated from the tablet.

PCI/Payments: do not store full card info; integrate with card terminal provider (external device) or a secure payment gateway.
